`k = 166-172 W/(m K)` temperature envelope, never a diagnostic fitted `m`.

## Figures

`Module_7/figures/` is written by the analysis scripts. The file names map one-to-one onto the figure numbers used in the report:

- `part_01_sensor_map.png` - rod geometry, hole positions, probe numbering (`python/analysis/sensor_map_figure.py`)
- `part_02_step_response.png` - six-channel step response (no calibration correction curves: the soak was skipped) (`python/analysis/step_response_figure.py`, default input `module_07_rod_interlock_trip_45C_40C.csv`)
- `part_03_stationary_profile.png` - stationary profile with both fits and both residual sets; the committed copy is titled `CRITERION RELAXED`, because the pre-registered criterion was not met (`python/analysis/stationary_fin_fit.py`)

All three exist and are regenerated by rerunning those three commands; nothing in them is hand-edited. Regenerating
them on 2026-11-02 after the documentation pass produced **byte-identical** PNGs, and the same rerun of the fit and
the diagnostics reproduced both JSONs and the profile CSV byte for byte — so the committed files are exactly what
the committed scripts emit. Diagnostic figures are not deliverable figures: the per-run check traces sit in
`figures/pilot_checks/<raw stem>_temperatures.png`, one file per checked run.

Every number that appears in a figure must be traceable to a fit result in `Module_7/data/processed/`, and vice versa. The
`part_03` numbers therefore come from `module_07_rod_stationary_40C_stationary_fit.json`, and the systematics quoted next to them
in the report come from `module_07_rod_stationary_40C_stationary_diagnostics.json` (written by
`python/analysis/stationary_diagnostics.py`).
